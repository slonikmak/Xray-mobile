# Проверка задачи 02

Проверено на ARM64 Android Emulator, API 37, с Xray-core/libXray v26.10.31 и синтетическими профилями. Для серверов использовался локальный Xray с исходящим подключением через хост; секреты и адреса пользователя в результатах не сохранены.

- `./gradlew :app:desktopTest :app:assembleDebug :app:lintDebug --console=plain` — успешно, 29 тестов. Тесты состояний используют подменённый адаптер и не заменяют проверку маршрутизации.
- Android запросил разрешение VPN; отказ не запустил соединение. Проверены отключённый экран и отказ (`01-disconnected.png`, `02-permission-denied.png`). При работе VPN показаны активный туннель и результат HTTPS-проверки (`03-connected.png`), при ошибке проверки состояние туннеля осталось активным (`05-check-failed.png`). Макеты: Pencil `eiHex` и `tRJf1`; VPN-тексты адаптированы к реальному состоянию. Подключение снято покадрово в обычной сборке (`10-connecting.png`); для снимка быстрой остановки использована временная сборка с двухсекундной задержкой очистки (`11-disconnecting-delayed.png`). Задержка удалена.
- **TCP/REALITY/vision, обычная сборка:** VPN подключился, HTTPS-проверка успешна, Chrome открыл сайт (`04-browser-reality.png`). На сервере наблюдались соединения TCP и UDP. Через `adb shell -T nc -u -W 4 -q 2 1.1.1.1 53` отправлен DNS-запрос и получен корректный ответ.
- **XHTTP/TLS, публичный сертификат, обычная сборка:** сервер за временным Cloudflare Quick Tunnel принимал TCP и UDP Xray. Ответы не доходили: Quick Tunnel буферизует потоковые ответы и не поддерживает SSE, поэтому полноценная проверка HTTPS через эту конфигурацию не прошла.
- Дополнительная попытка через временный LocalTunnel также не дала работающего соединения. Сохранённый исходный профиль содержит примерный адрес, поэтому использовать его как работающий сервер нельзя.
- **XHTTP/TLS, локальный тестовый сертификат:** во временной сборке для конкретного тестового сервера задан SHA-256 pin сертификата, без отключения проверки TLS. Браузер открыл HTTPS (`07-browser-xhttp-tls-pinned.png`), HTTPS-проверка приложения прошла (`06-xhttp-tls-pinned.png`), DNS по UDP вернул корректный ответ. Обычная сборка с системным доверием не проходила эту проверку на локальном тестовом CA; временное изменение сборки полностью удалено. Поэтому полноценная сквозная проверка XHTTP/TLS с обычной сборкой и работающим публичным сервером остаётся открытой.
- При XHTTP/TLS в тестовой сборке ответ сервиса определения IP в эмуляторе совпал с исходящим IP хоста, на котором работал тестовый сервер. Поскольку сервер и эмулятор используют одну внешнюю сеть, совпадение само по себе не доказывает маршрут; передачу также подтверждают записи приёма на Xray-сервере.
- `adb shell dumpsys connectivity` показал VPN с маршрутом `0.0.0.0/0` через `tun0` и `::/0 unreachable`; `adb shell ping6 -c 1 -W 2 2606:4700:4700::1111` вернул `No route to host`. При возврате из браузера интерфейс сохранил активную сессию. После остановки запись VPN исчезла, Chrome открыл страницу по HTTPS через обычную сеть (`08-browser-after-disconnect.png`).
- Прежняя подписка эмулятора восстановлена побайтно из резервной копии. Тестовый пользовательский CA удалён из Android, временные файлы сертификата удалены, обычная сборка переустановлена, тестовые серверы и публичные туннели остановлены.

## Проверка с подпиской провайдера

- После добавления поддержки `extra.xmux` и обновления подписки приложение импортировало все 5 полученных профилей: 3 XHTTP/TLS и 2 TCP/REALITY. Параметры в ссылке профиля сохранены.
- Один реальный профиль XHTTP/TLS проверен в обычной сборке с системным доверием TLS: Connection check успешен, Chrome открыл HTTPS (`09-provider-xhttp-browser.png`), DNS по UDP получил ответ. Внешний IPv4 при включённом VPN отличался от адреса прямого выхода хоста; значения адресов здесь не сохраняются.
- `dumpsys connectivity` показал активный VPN и `::/0 unreachable`. После отключения запись VPN исчезла, и браузер открыл HTTPS по обычной сети. Подписка и выбранный XHTTP-профиль оставлены в приложении; VPN отключён.

- Повторно проверены foreground-сервис и наличие уведомления, работа в фоне и восстановление интерфейса. Автотесты команд подтверждают отмену запуска, ошибки запуска и очистки, запрет нового запуска до завершения очистки и игнорирование запоздалых результатов. Конфигурация ядра содержит только выбранный VLESS outbound, без direct fallback; автоматическое переподключение не настроено.
- После последующего изменения Gradle-конфигурации прежний конфликт `org.jetbrains:annotations` больше не воспроизводится. `./gradlew :app:desktopTest :app:assembleDebug :app:lintDebug --console=plain` прошёл в основной рабочей копии и в чистой проверочной копии: 38 тестов, Android APK и lint. APK установлен на ARM64 эмулятор, данные подписки не изменились, реальное VPN-подключение и браузерный HTTPS проверены, VPN после проверки отключён. Для Gradle Wrapper восстановлена официальная SHA-256 сумма.
- Сборка предупреждает, что совместное применение Kotlin Multiplatform и Android application plugin при AGP 9 работает с устаревшими API; это переходная конфигурация. Kotlin также не заявляет AGP 9.5 в диапазоне полностью поддержанных версий для Kotlin 2.4.21. Для устойчивого обновления потребуется отдельная миграция структуры модулей или согласование поддерживаемых версий.

## Проверка после миграции AGP

- `./gradlew clean build --warning-mode all` — успешно в чистой копии: Android debug/release и lint, 38 desktop-тестов и 38 Android host-тестов. `./gradlew build --warning-mode all` также прошёл в основной рабочей копии. Общий код и тесты находятся в `:shared`, приложение — в `:app`; используется Kotlin 2.4.21 и поддерживаемый AGP 9.3.1.
- APK установлен поверх существующего на ARM64 эмуляторе, сохранённая подписка не изменилась (проверена контрольная сумма). С реальным профилем проверены VPN и успешная проверка интернета, браузер открыл HTTPS; VPN после проверки отключён. Прежнее предупреждение о совместимости KMP и AGP больше не появляется.
